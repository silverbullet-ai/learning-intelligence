# Flask Template Rendering

## Overview

In real-world web applications, HTML should be separated from Python code to keep projects organized and maintainable.

Flask provides the `render_template()` function to render HTML files stored inside the **templates** directory.

Internally, Flask uses the **Jinja2 Template Engine**, allowing HTML pages to display dynamic content generated by Python.

---

# Returning HTML Directly

Instead of returning plain text:

```python
@app.route("/")
def home():
    return "Welcome to Flask"
```

Flask can also return HTML directly:

```python
@app.route("/")
def home():
    return """
    <html>
        <body>
            <h1>Welcome to Flask</h1>
        </body>
    </html>
    """
```

The browser interprets the returned string as HTML and renders it as a webpage.

---

# Why Returning HTML in Python is Not Recommended

Although Flask allows HTML to be written directly inside Python, this approach becomes difficult to maintain.

Imagine writing:

- Navigation bars
- Forms
- Tables
- CSS
- JavaScript
- Footer
- Hundreds of HTML elements

inside one Python function.

Example:

```python
return """
<html>
<head>
...
</head>

<body>

<nav>
...
</nav>

<div>
...
</div>

<footer>
...
</footer>

</body>
</html>
"""
```

Large applications quickly become unreadable.

Therefore, Flask encourages keeping HTML in separate files.

---

# Flask Template Rendering

Flask provides the **render_template()** function.

Import it using:

```python
from flask import Flask, render_template
```

Example:

```python
@app.route("/index")
def index():
    return render_template("index.html")
```

Instead of returning HTML directly, Flask loads the HTML file and sends it to the browser.

---

# Templates Folder

Flask automatically looks for HTML files inside a folder named:

```
templates/
```

Project structure:

```
flask-project/
│
├── app.py
│
└── templates/
    ├── index.html
    ├── about.html
    └── contact.html
```

> **Important:** The folder name must be exactly **templates**.

Incorrect names:

- template
- Templates
- html
- pages

Flask will not detect them automatically.

# Rendering an HTML Page

Suppose the following file exists:

```
templates/
└── index.html
```

Route:

```python
@app.route("/index")
def index():
    return render_template("index.html")
```

When a user visits:

```
http://localhost:5000/index
```

Flask performs the following steps:

```
Browser

↓

/index

↓

Flask Route

↓

render_template("index.html")

↓

templates/index.html

↓

HTML Response

↓

Browser
```

# Rendering Multiple Pages

Templates:

```
templates/

├── index.html
├── about.html
└── contact.html
```

Routes:

```python
@app.route("/index")
def index():
    return render_template("index.html")


@app.route("/about")
def about():
    return render_template("about.html")


@app.route("/contact")
def contact():
    return render_template("contact.html")
```

URL Mapping

| URL | Template |
|------|----------|
| /index | index.html |
| /about | about.html |
| /contact | contact.html |

# Complete Example

```python
from flask import Flask, render_template

app = Flask(__name__)

@app.route("/")
def home():
    return "<h1>Welcome to Flask</h1>"

@app.route("/index")
def index():
    return render_template("index.html")

@app.route("/about")
def about():
    return render_template("about.html")

if __name__ == "__main__":
    app.run(debug=True)
```

# Understanding Jinja2

Whenever we use:

```python
render_template()
```

Flask internally uses the **Jinja2 Template Engine**.

Jinja2 allows HTML pages to become dynamic by receiving data from Python.

Instead of:

```html
<h1>Welcome User</h1>
```

we can write:

```html
<h1>Hello {{ name }}</h1>
```

Python:

```python
return render_template(
    "index.html",
    name="Aahish"
)
```

Output:

```
Hello Aahish
```

Jinja2 also supports:

- Variables
- Loops
- Conditions
- Template inheritance

These concepts are explored in later sections.

# Why Use Templates?

Instead of mixing frontend and backend:

```
Python

↓

HTML

↓

CSS

↓

JavaScript
```

Flask separates responsibilities:

```
Backend

app.py

↓

render_template()

↓

Frontend

index.html
```

Benefits:

- Cleaner code
- Easier maintenance
- Better readability
- Separation of concerns
- Easier collaboration between frontend and backend developers

# Common Error: TemplateNotFound

Suppose the route is:

```python
return render_template("index.html")
```

but the file does not exist.

Error:

```
TemplateNotFound: index.html
```

Flask searched inside:

```
templates/
```

but could not find the file.

# Common Beginner Mistakes

## Forgetting render_template()

Incorrect:

```python
return "index.html"
```

Correct:

```python
return render_template("index.html")
```

---

## Wrong Templates Folder Name

Incorrect:

```
template/
```

Correct:

```
templates/
```

---

## Wrong File Name

Python:

```python
render_template("index.html")
```

Actual file:

```
index1.html
```

Result:

```
TemplateNotFound
```

---

## Placing HTML Outside templates/

Incorrect:

```
project/

index.html
```

Correct:

```
project/

templates/

index.html
```

---

# Best Practices

- Keep HTML inside the `templates` directory.
- Use `render_template()` instead of returning HTML strings.
- Give template files meaningful names.
- Separate frontend and backend responsibilities.
- Organize templates as the application grows.

---

# Key Takeaways

- Flask uses `render_template()` to render HTML pages.
- HTML files must be stored inside the `templates` directory.
- Flask automatically searches for templates inside the `templates` folder.
- Returning HTML directly from Python is suitable only for very small examples.
- Jinja2 is Flask's default template engine.
- Separating frontend and backend code makes applications easier to maintain and scale.
